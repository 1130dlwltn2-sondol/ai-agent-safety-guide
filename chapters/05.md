# 5장. 승인받아야 하는 행동

## 학습 목표

1. 전송, 구매, 삭제, 게시처럼 승인이 필요한 행동을 구분할 수 있다.
2. 승인 카드를 만들어 실제 보내기 전에 점검하는 절차를 실습할 수 있다.

## 선행 개념

4장에서 외부 문서의 숨은 지시를 다루었다. 이 장에서는 AI가 스스로 행동할 때의 안전장치를 다룬다. 에이전트는 도구에 연결되어 실제로 이메일을 보내거나 파일을 지울 수 있다. 그래서 중요한 행동 앞에는 사람의 승인을 넣는다.

용어 정리:
- 승인 카드: 보내기 전에 받는 사람, 내용, 첨부, 외부 공유 여부를 점검하는 체크리스트.
- 되돌릴 수 없는 행동: 한 번 하면 취소가 어려운 행동. 전송, 결제, 삭제, 공개 게시가 대표적이다.
- 확인 절차: 에이전트가 민감한 단계 전에 멈추고 사람에게 물어보는 설계.

## 쉬운 설명

OpenAI의 안내에 따르면, 에이전트는 구매 완료나 이메일 발송 같은 중요한 행동 전에 최종 확인을 받도록 설계되는 경우가 많다 [S4]. 확인을 요청받았을 때는 "그 행동이 맞는지, 공유되는 정보가 적절한지"를 꼼꼼히 살펴야 한다.

왜 승인이 필요할까. 1장에서 본 Anthropic의 공개 사례를 떠올려 보자. 평가 과정에서 AI가 제출하면 안 되는 실제 웹 양식을 제출한 경우가 있었다 [S1]. 지시가 모호했거나 환경 설정이 잘못된 탓이었다. 사람 눈으로 한 번만 확인했어도 막을 수 있는 종류의 실수다.

승인이 필요한 행동의 기준은 간단하다.

1. 외부로 나가는가 (전송, 게시)
2. 돈이 오가는가 (구매, 결제)
3. 되돌리기 어려운가 (삭제)
4. 남에게 영향을 주는가 (공유)

하나라도 해당하면 승인 카드를 쓴다. 승인 카드는 거창한 것이 아니다. 보내기 전에 체크하는 다섯 줄이면 된다.

## 가상 데이터 예시

아래는 이 장 실습에 쓰는 가상의 이메일 발송 업무다. 전부 만들어 낸 것이다.

가상의 이메일 발송 업무:
- 받는 사람: 가상 고객사 담당자 (가상 이메일 주소)
- 제목: 가상 프로젝트 진행 상황 안내
- 내용: 10월 진행률 70%, 다음 회의는 11월 첫째 주
- 첨부: 가상 진행 보고서.pdf

## 단계별 실습

1. 위의 가상 이메일 발송 업무를 메모장에 복사해 둔다. 필요하면 가상의 예시를 새로 만들어도 된다.
2. 아래 복사용 프롬프트를 AI에 입력하고, 결과를 복사해 별도 Markdown 메모에 보관한다.
3. 결과를 원문(위의 발송 업무)과 대조하고, 승인 체크표에 빠진 항목이 없는지 오류를 기록한다.
4. 누락된 항목을 수정해 두 번째 결과를 얻는다. 예를 들어 첨부 파일의 내용이 맞는지 점검 항목이 있는지 확인한다.

### 실습 과제

가상 이메일 발송의 승인 카드를 만든다.

### 복사용 프롬프트

```
이 작업은 [가상 고객에게 안내 메일 보내기]다. 실제 전송은 하지 말고 받는 사람·내용·첨부·외부 공유 정보를 승인 체크표로 만들어줘.
```

### 예상 결과

AI는 대략 다음과 같은 승인 카드를 돌려준다. 실제 전송은 하지 않는다.

- 받는 사람: 가상 고객사 담당자 (주소 확인 필요)
- 제목: 가상 프로젝트 진행 상황 안내
- 내용 점검: 진행률 70%, 다음 회의 일정 표기 확인
- 첨부: 가상 진행 보고서.pdf (최신본인지 확인)
- 외부 공유 여부: 외부 발송이므로 승인 필요
- 최종 승인: [ ] 사람 확인 후 발송

### 흔한 오류와 해결책

- 오류: 승인 카드 없이 바로 "보내 드릴까요"라고 했다. 해결: 카드 형식을 지정해 다시 요청한다. 형식은 "받는 사람, 내용, 첨부, 외부 공유, 최종 승인" 다섯 줄이다.
- 오류: 첨부 파일 점검을 빠뜨렸다. 해결: 첨부 파일명과 버전 확인 항목을 추가한다.
