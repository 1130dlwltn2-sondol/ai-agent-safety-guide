# 6장. 사실 확인과 출처 추적

## 학습 목표

1. AI의 주장을 사실, 의견, 추측으로 나누어 볼 수 있다.
2. 날짜를 사건 발생일과 공개일로 구분해 표로 정리할 수 있다.

## 선행 개념

5장에서 승인 절차를 배웠다. 이 장에서는 AI가 내놓은 내용 자체를 검증하는 법을 다룬다. AI는 그럴듯하게 말하지만, 날짜를 섞거나 확인되지 않은 내용을 사실처럼 말할 수 있다.

용어 정리:
- 사건 발생일: 일이 실제로 일어난 날짜.
- 공개일: 그 일이 세상에 알려진 날짜. 보도일이나 발표일이 여기에 해당한다.
- 1차 출처: 사실을 직접 발표한 기관의 자료. 공식 발표문, 규제기관 보도자료 등.
- 2차 출처: 1차 출처를 받아 쓴 기사나 정리 글.

## 쉬운 설명

이 책에서 쓰는 핵심 사례로 연습해 보자. 2026년 10월 9일 Anthropic이 내부 평가 사례를 공개했다 [S1]. 여기서 10월 9일은 공개일이다. 각 사례가 언제 발생했는지는 공개 글에 자세히 나와 있지 않다. "10월 9일에 사건이 일어났다"고 쓰면 틀리다. "10월 9일에 공개되었다"가 맞다.

영국 ICO의 경우도 같다. 2026년 10월 8일에 보도자료를 내고 의견 수렴을 시작했다 [S2][S3]. 의견 수렴 마감은 2026년 11월 20일이다. "10월 8일에 규제가 시작되었다"가 아니라 "10월 8일에 의견 수렴이 시작되었다"가 정확한 표현이다.

사실 확인의 순서는 이렇다.

1. AI의 주장에서 검증 가능한 부분만 추린다.
2. 각 주장의 날짜가 사건일인지 공개일인지 구분한다.
3. 1차 출처(공식 발표)를 열어 직접 확인한다.
4. 확인되지 않은 것은 "미확인"이라고 쓴다.

이 책의 조사 노트도 같은 원칙을 지켰다. 원문 PDF는 수집하지 않았고, 웹페이지를 PDF 원본처럼 표기하지 않았다. 커뮤니티 반응은 정성적 신호로만 쓰고 수요 통계처럼 쓰지 않았다.

## 가상 데이터 예시

아래는 이 장 실습에 쓰는 가상의 출처 3개다. 전부 만들어 낸 것이다.

- 가상 기사 A: "AI가 고객 정보를 유출했다" (2026-10-10 보도)
- 가상 기사 B: "AI 오류는 테스트 중 발견" (2026-10-11 보도)
- 가상 공식 문서: "내부 평가 사례 공개" (2026-10-09 공개)

## 단계별 실습

1. 위의 가상 출처 3개를 메모장에 복사해 둔다. 필요하면 가상의 예시를 새로 만들어도 된다.
2. 아래 복사용 프롬프트를 AI에 입력하고, 결과를 복사해 별도 Markdown 메모에 보관한다.
3. 결과를 원문(위의 3개 출처)과 대조하고, 사실과 추측이 섞이지 않았는지, 날짜 구분이 맞는지 오류를 기록한다.
4. 누락된 항목을 수정해 두 번째 결과를 얻는다. 예를 들어 기사 A의 "유출"이 확인된 사실인지 추측인지 다시 판단한다.

### 실습 과제

기사 2개와 공식문서 1개의 주장 비교표를 작성한다.

### 복사용 프롬프트

```
아래 3개 출처에서 확인된 사실/주장/추측을 분리하고 날짜를 사건일과 공개일로 나눠 표로 정리해줘.
```

### 예상 결과

AI는 대략 다음과 같은 표를 돌려준다.

| 출처 | 확인된 사실 | 주장/추측 | 날짜 구분 |
|------|-------------|-----------|-----------|
| 가상 공식 문서 | 내부 평가 사례를 공개함 | - | 2026-10-09 공개일 |
| 가상 기사 A | (공식 문서 인용) | "유출" 표현은 확인 안 됨 | 2026-10-10 보도일 |
| 가상 기사 B | 테스트 중 발견 언급 | - | 2026-10-11 보도일, 사건일 미확인 |

### 흔한 오류와 해결책

- 오류: 보도일을 사건일로 썼다. 해결: 날짜마다 "이것은 보도일인가, 사건일인가"를 묻는다.
- 오류: 기사의 추측을 사실란에 넣었다. 해결: "확인된 사실"에는 1차 출처에서 직접 확인한 것만 넣는다.
